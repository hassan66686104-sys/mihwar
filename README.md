# مِحْوَر

**ساحة النقاش الصفّي للتربية الإسلامية**: «نتحاور بأدب، ونستدل بعلم، ونختلف باحترام».

منصة ويب عربية (RTL) لإدارة النقاش داخل الحصة. يدير المعلم الجلسة من لوحته، ويدخل الطلاب من هواتفهم برمز الجلسة ورمز شخصي، دون حسابات.

---

## ما الذي تقدمه المنصة؟

| الجانب | التفاصيل |
|---|---|
| أنماط النقاش | المنتدى الحواري، والمناظرة بين الفرق بمراحل، والنقاش بالدور (رفع اليد)، والتصويت |
| أنواع المشاركة | رأي أو تفسير، وآية، وحديث، ودليل فقهي، وشاهد من الكتاب المدرسي، ومثال واقعي، ورد أو تعقيب، وسؤال، وخلاصة |
| الأدلة | حقول خاصة بكل نوع: نص الآية والسورة ورقمها، ومصدر الحديث، ودرجة الحديث (اختيارية، ولا يختلقها النظام)، والكتاب والصفحة، ووجه الاستدلال |
| المؤقت | محفوظ على الخادم بوقت انتهاء ثابت. يحسب كل جهاز المتبقي بفارق ساعته عن ساعة الخادم. يدعم الإيقاف والاستئناف والإضافة |
| الإشراف | مراجعة المشاركات قبل ظهورها، والقبول والرفض والحذف والتثبيت، وإغلاق الردود، وتصنيف المعلم، وملاحظات خاصة، وإخراج الطلاب، وسجل إجراءات لا يُعدَّل |
| التقرير | أرقام مؤكدة من قاعدة البيانات، وتقييم يدوي من 1 إلى 4 مع خيار «لم يُقيّم»، وقراءة تلقائية مفصولة وموسومة، وتصدير CSV، وطباعة أو حفظ PDF |
| شاشة العرض | السؤال المحوري، والمؤقت، ورمز QR، والمتحدث الحالي، والمرحلة، والمشاركات المقبولة، ونتائج التصويت |
| الجلسة التجريبية | «التوكل على الله والأخذ بالأسباب» بأسماء وهمية موسومة بوضوح. الحديث فيها منسوب لسنن الترمذي، ودرجته متروكة فارغة عمدًا ومصنفة «يحتاج إلى تحقق» |

## البنية والأمان

- **الواجهة:** React 19 وTypeScript وVite وTailwind 4 وRecharts.
- **الخلفية:** Supabase (Postgres وAuth وRealtime). لا يوجد خادم خاص بالمشروع.
- **الكتابة:** كل عملية كتابة تمر عبر دوال RPC محمية (`security definer`)، وكل دالة تتحقق من:
  - المعلم: `auth.uid()` وملكيته للصف أو الجلسة.
  - الطالب: رمز وصول عشوائي (64 خانة) يُحفظ في القاعدة مجزّأً (sha256) فقط.
- **قراءة الجداول:**
  - RLS مفعّل على كل جداول `mh_`.
  - المعلم يقرأ بياناته فقط عبر سياسات SELECT.
  - الزائر (anon) لا يملك أي صلاحية على الجداول.
  - لا توجد سياسات INSERT أو UPDATE أو DELETE لأي دور.
- **الصلاحيات تُفرض على الخادم:** إخفاء الأزرار في الواجهة ليس هو الحماية. الحماية في قاعدة البيانات، وتشمل:
  - إغلاق الجلسة والإيقاف المؤقت وانتهاء الوقت.
  - حدود المشاركات.
  - قيود المرحلة والفريق في المناظرة.
  - دور المتحدث في النقاش بالدور.
  - صوت واحد لكل طالب، بمفتاح أساسي يمنع التكرار حتى مع الطلبات المتزامنة.
- **لا أسرار في الواجهة:** تستخدم الواجهة المفتاح العام (publishable/anon) فقط. لا يوجد مفتاح service_role، ولا رابط سري للمعلم، ولا كلمة مرور مضمنة في الكود.
- **التحديث الفوري:**
  - يرسل محفز في القاعدة إشعار «تغيّر» بلا بيانات إلى قناة الجلسة.
  - يعيد كل جهاز جلب حالته عبر دالته المحمية، فلا تتسرب بيانات عبر البث.
  - إذا انقطعت القناة يتحول الجهاز إلى تحديث دوري كل 5 ثوانٍ، ويظهر ذلك في شارة الاتصال.
- **منع التكرار:** كل مشاركة تحمل معرّفًا من الجهاز (`client_id`)، فلا تتكرر عند النقر المزدوج أو إعادة الإرسال بعد انقطاع الشبكة. تُحفظ المسودة على الجهاز حتى يؤكد الخادم الحفظ.
- **بادئة الجداول:** كل جداول المشروع تبدأ بـ `mh_` حتى تتعايش مع جداول أخرى في مشروع Supabase نفسه.

## الإعداد على Supabase

1. أنشئ مشروعًا، أو استخدم مشروعًا قائمًا (الجداول كلها بالبادئة `mh_`).
2. طبّق ملفات `supabase/migrations/` **بالترتيب** من SQL Editor أو عبر `supabase db push`. الملفات قابلة لإعادة التشغيل.
3. من Authentication ← Providers فعّل Email.
   - إذا كان «Confirm email» مفعّلًا، فسيصل المعلم الجديد بريد تأكيد قبل أول دخول، والواجهة تعرض له ذلك.
   - أضف عنوان موقعك المنشور في Authentication ← URL Configuration (Site URL وRedirect URLs) حتى يعمل رابط استعادة كلمة المرور.
4. انسخ `.env.example` إلى `.env.local` واملأ:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`: المفتاح publishable، **وليس** service_role.

## التشغيل محليًا

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # فحص الأنواع + بناء الإنتاج في dist/
```

انظر [docs/TESTING.md](docs/TESTING.md) لتفاصيل الاختبارات وجدول اختبارات القبول بحالتها الفعلية. باختصار:

- `npm run test:db`: 24 اختبارًا لقاعدة البيانات على PostgreSQL محلي، تغطي الصلاحيات وRLS والانتحال والتزامن والحدود والمؤقت والتصويت والتقرير.
- `npm run test:e2e`: 10 اختبارات متصفح بعدة سياقات في الوقت نفسه (معلم وطالب على هاتف وطالب على حاسوب). تعمل على بيئة محلية فيها Supabase Auth وPostgREST الحقيقيان وقناة Realtime مُحاكاة.

## النشر

### Vercel

1. استورد المستودع. الإعدادات الافتراضية لـ Vite كافية: البناء `npm run build` والمخرجات `dist`.
2. أضف المتغيرين `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` في Environment Variables.
3. يتولى `vercel.json` إعادة توجيه المسارات إلى `index.html`.

### Netlify

البناء `npm run build` والنشر من `dist`، مع المتغيرين نفسيهما. يتولى `public/_redirects` إعادة التوجيه.

بعد النشر أضف عنوان الموقع في إعدادات Auth في Supabase كما في الخطوة 3 أعلاه.

## النسخ الاحتياطي والاستعادة

- **النسخ التلقائي:** يأخذ Supabase نسخًا احتياطية يومية حسب خطتك (Database ← Backups).
- **النسخ اليدوي:**
  ```bash
  supabase db dump --data-only -f mihwar-data.sql   # يتطلب Supabase CLI وربط المشروع
  ```
  لنسخ جداول المشروع فقط عبر `pg_dump`، استخدم `--table 'public.mh_*'`.
- **الاستعادة:** طبّق الـ migrations على قاعدة فارغة، ثم نفّذ ملف البيانات بـ `psql`.
- **التقارير:** صدّر من صفحة كل تقرير (CSV أو PDF) قبل استخدام «حذف الجلسات القديمة» في لوحة التحكم.

## ما اكتمل وما لم يكتمل

| الحالة | البند |
|---|---|
| ✅ مكتمل ومختبر | الأنماط الأربعة، والأدلة، والمؤقت، والإشراف، والتقرير، وشاشة العرض، والجلسة التجريبية، والأمان (انظر docs/TESTING.md) |
| ⚠️ مختبر على بيئة محلية فقط | التدفق الكامل في المتصفح لم يُختبر على مشروع Supabase السحابي، لأن بيئة التطوير لا تصل إلى supabase.co. تحقّقنا على المشروع السحابي من وجود الجداول والدوال والسياسات والصلاحيات فقط |
| ⚠️ مُحاكى في الاختبار | قناة Realtime: الاختبارات استخدمت محاكيًا لبروتوكول البث. خادم Supabase Realtime الحقيقي لم يُختبر بعد. إن تعطّل، يتحول التطبيق تلقائيًا إلى التحديث الدوري (5 ثوانٍ) ويظهر ذلك للمستخدم |
| ❌ لم يُنفَّذ | اختبار حمل بعدد صف كامل (30 طالبًا أو أكثر) في الوقت نفسه |
| ⚠️ منشور ولم يُختبر آليًا | الموقع منشور على Netlify (`https://mihwar-kfjg.netlify.app`) ويُبنى تلقائيًا من الفرع main. نجح البناء، لكن بيئة التطوير لا تصل إلى الموقع المنشور، فلم يُختبر التدفق عليه آليًا |
| ❌ غير مدعوم | التحقق الآلي من صحة الأحاديث أو درجاتها: المنصة لا تختلق درجات، وتترك للمعلم التصنيف «يحتاج إلى تحقق» |
